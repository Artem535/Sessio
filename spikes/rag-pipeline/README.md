# RAG-суфлёр Sessio — схема и пояснения

Диаграмма: [`rag-pipeline.html`](rag-pipeline.html) (открыть в браузере; тёмная/светлая
тема, экспорт PNG/SVG). Исходник диаграммы: `rag-pipeline.architecture.json`
(рендер — skill `archify`). Ветка `feat/185-rag-core`, issue #185, версия 0.2.49.

## Live-путь (во время звонка)

1. **ASR-транскрипт → реплика.** В поиск уходят реплики обеих ролей: в соло-тестах
   весь звук помечается как practitioner, а вопросы специалиста тоже worth searching.
   ASR не ставит «?» и коверкает слова — это учтено ниже.
2. **Router.** v1 — детерминированные правила: «?», вопросительные слова RU,
   глаголы-просьбы («расскажите», «подскажите»…); 0 мс, 0 памяти. v2 (opt-in) —
   линейная голова (логрегессия, 4 класса) поверх того же эмбеддинга реплики;
   обучена на draft-датасете (LOO 0.881), переобучение на реальных транскриптах
   обязательно до продакшена. Класс «ignore» не ищется; продолжения ищутся.
   Отдельная настройка «search every phrase» обходит роутер целиком.
3. **Query rewrite.** Три режима (настройка): правила v1 (срез ведущего «А»,
   подстановка темы для анафоры); локальная LLM — второй экземпляр модели
   суфлёра на потоке воркера (однозапросный движок суфлёра не занимается),
   ответ ограничен JSON-схемой `{"query": ...}`; облако — OpenAI-совместимый
   движок суфлёра, payload обезличивается Pseudonymizer'ом (имена/телефоны/почты
   → метки), ответ раз-обезличивается локально. Отказ LLM → откат на правила.
4. **NER fuzzy-match.** Словарь сущностей вики (проекты/клиенты/продукты)
   матчится против реплики: нормализация (ё→е, регистр) + Левенштейн по
   кодпоинтам с порогом по длине токена (≥4 симв. — 1 правка, ≥8 — 2).
   Найденные сущности дают канонический вариант запроса и буст документов,
   которые их содержат. Это чинит именно STT-искажения имён.
5. **Embedder.** embeddinggemma-2-270m int8 (.litertlm) через LiteRT-LM, CPU
   4 потока, ~130 мс на запрос. Префикс рецепта `task: search result | query: `
   добавляет rag-core, не обёртка: один энкодер служит и поиску, и голове роутера.
6. **Hybrid search.** По каждому варианту запроса (LLM-rewrite, rules-rewrite,
   реплика без контекста, предыдущая реплика, канонические имена) берутся
   dense top-50 (HNSW cosine) и FTS top-50 (BM25, русский стеммер); выдачи
   сливаются RRF (k=60), документы с сущностями получают буст, затем
   doc-dedup (лучший чанк документа) и top-k. Мульти-вариантность компенсирует
   кривую текущую фразу чистыми вариантами.
7. **Карточка «Wiki hint».** Markdown-рендер (QML `Text.MarkdownText` и
   QLabel), snippet обрезан до 600 кодпоинтов по границе абзаца/слова,
   кликабельные ссылки (относительные `/doc/…` резолвятся против Outline URL).
   Живёт в QML NotesWorkspace (bridge-payload) и в QWidget-панели суфлёра.
   Отмена по generation: устаревшие результаты не показываются.

Бюджет: роутер 0 мс + rewrite 1–3 с (local CPU) + эмбеддинг ~130 мс × вариантов
+ поиск единицы мс. Без rewrite — ~150 мс на реплику.

## Background-путь (индексация)

- **Connector.** Outline `documents.list`/`collections.list`, пагинация 100,
  429-retry по Retry-After, allowlist коллекций, токен из настроек (не в логах).
  Синк по ревизиям: неизменённые документы пропускаются.
- **Чанкер.** Структурный Markdown: путь заголовков от титула, таблицы и
  code-фенсы целы, oversized-блоки режутся с повтором шапки таблицы, лимит
  1800 кодпоинтов. Точный порт спайка 12.11 (кросс-чек 200 документов, 0 расхождений).
- **Embedder (doc-префикс).** `title: none | text: ` + титул + путь + текст;
  ~550 мс/чанк на CPU. Первичная индексация 7789 чанков ≈ 70 мин CPU или
  ~15 мин на GPU Buran (Ollama embeddinggemma-2:270m, батч 64); дальше инкремент.
- **IndexStore (LadybugDB, форк Kuzu).** Таблицы Document / Chunk / Entity,
  FTS-индекс с русским стеммером и HNSW cosine-индекс. Prebuilt liblbug 0.22.3 +
  офлайн-расширения fts/vector (без сети в рантайме). Exclusive-лок: один
  процесс-владелец (RagWorker); для офлайн-запросов копируется директория БД.

## NER-словарь

- Экстракция: lfm3 1.7B Q8_0 (SFT-экспорт v11) в **собственном GPU-контейнере**
  `ollama-rag` (ollama:latest, `--gpus all`, порт 11436). Shared-сервис :11435
  работает без GPU-offload — не трогается.
- 480 документов → 1351 сущность → 1180 уникальных имён после чистки мусора
  (маскированные телефоны) и слияния коллизий имён между типами.
- Загрузчик `load_entities` (C++, Qt6Core) льёт `entities.json` в Entity-таблицу;
  upsert объединляет списки документов. Воркер читает словарь при старте
  (`RAG: entities N` в логе).

## Принципы и деградация

- Офлайн-first: без сервера и MCP. Облако допускается только для rewrite и
  только обезличенно (правило проекта); индексация и поиск полностью локальны.
- Выключенный RAG, отсутствующий рантайм или индекс → суфлёр работает как раньше;
  причины отказа пишутся в лог (`RAG worker: …`, `RAG: …`).
- Модель эмбеддинга находится сама (настройки → рядом с бинарником → dev-кэш),
  так что включения чекбокса достаточно.
- Настройки (диалог настроек → транскрипция → «Wiki hints»): включатель,
  search-every-phrase, trained-router-head, режим rewrite (rules/local/cloud),
  Outline URL/токен/allowlist, путь к embedding-модели.

## Артефакты и команды

- Индекс приложения: `~/.local/share/Sessio/Sessio/rag/index.lbug` (директория).
- Модель: `~/.cache/sessio-rag/models/embeddinggemma-2-text-270m.litertlm`.
- LadybugDB: `~/.cache/sessio-rag/ladybug/` (lib + extension/{fts,vector}).
- Запуск: `LD_LIBRARY_PATH=~/.cache/sessio-litert-lm/install/lib:~/.cache/sessio-rag/ladybug ./build-release/Sessio`.
- Экстракция NER: `spikes/rag-entities/extract_entities.py` (env `OUTLINE_API_TOKEN`,
  `OLLAMA_URL`); загрузка: `spikes/rag-entities/load_entities.cpp`.
- Индексация вики на GPU: `spikes/rag-indexer/indexer.py` (Buran).
- Sanity-чек эмбеддинга: `spikes/rag-embed-sanity/` (PASS, отчёт SANITY-REPORT.md).
- Тесты: 63 rag-теста (чанкер 10, роутер 9, rewrite 5, голова 3, сущности 5,
  коннектор 5, индекс 6, поиск 11, воркер 9).
