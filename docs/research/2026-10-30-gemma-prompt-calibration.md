# Калибровка промптов Gemma 4 E4B

Дата: 2026-10-30. Проверены официальные материалы Google и код Sessio. Запусков модели и изменений production-промптов в исследовании нет. Предложения ниже — гипотезы для сравнения, а не доказанные улучшения.

## Официальные рекомендации и границы применимости

Gemma 4 поддерживает native `system` role и формат `<|turn>system/user/model` с окончанием `<turn|>`. Старое указание «только user/model, без system» относится к Gemma 3 и ниже. Текущие `gemmaSystemTurn`/`gemmaUserTurn` в `prompter_pipeline.cpp` соответствуют новому формату. Переносить инструкции в user по старому гайду не нужно. Специальные delimiters строк из раздела tool use не относятся к нашему обычному JSON. [Gemma 4 formatting](https://ai.google.dev/gemma/docs/core/prompt-formatting-gemma4), [старый формат](https://ai.google.dev/gemma/docs/core/prompt-structure).

Thinking включается `<|think|>` в system. Официальный пример для **E2B/E4B OFF** заканчивается обычным model prefix; пустой thought channel для подавления ghost thinking предусмотрен для **12B/26B/31B**. Текущий renderer E4B не требует такого дополнения. Включение thinking — отдельный эксперимент с runtime/schema и задержкой, а не универсальное улучшение промпта. [Thinking in Gemma](https://ai.google.dev/gemma/docs/capabilities/thinking).

Model card подтверждает E4B, многоязычность и system. Номинальный контекст E4B — 128K, но активное окно Sessio задаётся в `sessio_litert.h` как 4096 tokens. Увеличение окна требует проверки конкретного LiteRT artifact/runtime. [Gemma 4 model card](https://ai.google.dev/gemma/docs/core/model_card_4).

Общий гайд Google рекомендует ясные инструкции, согласованный формат few-shot примеров и экспериментальный подбор их количества; избыток примеров может подстраивать ответы под демонстрации. Сложную работу предлагается делить на этапы, сложный JSON задавать structured output. Это руководство **Gemini**: перенос в E4B — проверяемая гипотеза, а не специальная гарантия Gemma. Документ не доказывает превосходства RU/EN инструкций или оптимальной температуры для нашего extraction. [Google prompt design strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies).

## Наблюдения в текущем коде

| Место | Проблема | Предлагаемая проверка |
|---|---|---|
| `extract.txt` | Для встречи требует обоих участников, но допускает одностороннее объявление; пример F содержит одного участника. | Указать только явно связанных с действием известных участников. Проверить внешнюю встречу без согласия собеседника. |
| `extract.txt` | Стартовый образец содержит `kind:"accept\|cancel"`. Демонстрации показывают строки реплик, но не внешний JSON с `new_utterances`, `call_date`, `calendar`. Сами строки соответствуют формату поля `new_utterances`. | Показать реальное enum-значение; проверить пользу примера полного payload. Schema защищает синтаксис, но не семантику. |
| `match.txt` | Упоминает `revise`, хотя extraction выдаёт accept/cancel и ниже описывает перенос через accept. | Единый словарь; парные примеры новой встречи и переноса существующей. |
| `live_points.txt` | Требует сохранять tentative options, но `Use OBS` превращается в «выбран OBS». | Отдельные примеры предложения без принятия и явно принятого решения. |
| `live_points.txt` | Формат примеров отличается от known_points/utterances; OBS-пример близок к model smoke case. | Настоящие JSON-примеры; OBS оставить development case, holdout сменить темы/формулировки. |
| `summary_leaf.txt` | Пустой JSON-шаблон содержит одну пустую задачу, хотя задач может не быть; законченного положительного примера нет. | Показывать tasks:[] и отдельно короткий grounded пример с полной задачей. |
| `summary_overview.txt` | Требует рассказать, как разговор закончился, хотя notes могут этого не содержать. | Завершение описывать только при наличии подтверждения. Это риск, ещё не воспроизведённый дефект. |

`SetApplyPromptTemplateInSession(false)` исключает повторное наложение chat template. Runtime использует greedy decoding (k=1, temperature 0), schema в GenerateOptions и резерв 1024 output tokens. Сохранить эти параметры в первом сравнении.

Текущие размеры UTF-8: extract 5774, match 3933, live points 1280, leaf 1099, overview 756 bytes. Notes используют консервативный входной лимит 4096-1024-128 **bytes**, поэтому удлинение инструкции уменьшает payload и меняет chunking. Русский текст может занимать больше UTF-8 bytes: перевод всех инструкций на русский не является нейтральной заменой.

## Контролируемая калибровка

1. **Baseline:** зафиксировать hashes prompts, artifact, backend, decoding, schema и бюджеты. Local/cloud и CPU/GPU не смешивать.
2. **B1 — ясность:** устранить противоречия participants, tentative/accepted, accept/revise и условность завершения. Сохранить язык и сопоставимый бюджет. Сравнить фиксированные фрагменты; отдельно измерить end-to-end влияние chunking.
3. **B2 — примеры:** B1 без примеров против одного-двух коротких примеров реального JSON: содержательное решение и пустой результат/обрывок. Менять только этот фактор.
4. **B3 — язык:** RU/EN с одинаковым смыслом и теми же русскими данными. Считать bytes, реальные prefill tokens, chunks и latency; заранее не объявлять победителя.
5. **B4 — thinking:** опциональное отдельное сравнение после B1–B3 с учётом schema/runtime и общего token budget. Не включать в пользовательскую сборку без измерения пользы.

Синтетические случаи: приветствия/звук, обрывок ASR, проблема без решения, предложение/принятие, отказ/отрицание, две встречи/перенос, разные получатели, поздняя коррекция, число как evidence ID, инструкция внутри расшифровки, технический и консультационный разговоры. Development/holdout различаются темами, именами, датами и формулировками. Демонстрации из prompt не считаются holdout.

Метрики отдельно: JSON/schema/evidence validity, precision/recall действий, ложные обязательства, пропуски/слияния встреч, неподтверждённые факты, шум/дубли, длина/понятность текста, prefill/decode tokens, вызовы и latency. При greedy повтор одного входа не заменяет разнообразия случаев. Принимать новый prompt после сравнения с baseline без ухудшения критических отрицательных случаев; до этого новый текст остаётся кандидатом.
