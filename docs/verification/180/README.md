# Проверка контракта суфлёра (#180)

Состояние: работа не завершена; результаты синтетического smoke не являются
оценкой качества модели. Реальные реплики в этот каталог не записываются.

- Приложение и штатные тестовые цели собраны в `build-release`;
  CTest для суфлёра: 83/83. При линковке LiveKit использована локально
  установленная библиотека curl с символами `CURL_OPENSSL_4`.
  Включаемый debug-лог синтетического ответа проверен отдельно.
- Гейт шести промптов проходит; тесты гейта проверяют, в том числе, отказ при
  изменённом промпте, отсутствии файла, изменении набора задач и встроенном
  промпте. Экспорт старого `sft_v3.jsonl` отвергнут: системный промпт
  `summary_leaf` отличается. Внешний `sessio_v3_build.py` дополнен
  preflight и проверяемым экспортом; существующий трёхзадачный вариант
  останавливается до записи данных и вызовов учителя. Проверка отказа
  выполнена, исходный датасет не пересобирался. Патч внешнего файла
  сохранён отдельно от репозитория среди артефактов проверки.
- Smoke `AgreementWithoutDeadlineAsksForIt`: модель загрузилась на CPU,
  схема extract принята (`schema`), 49 декодированных токенов, но ожидаемое
  соглашение не извлечено (0 событий вместо 1). Тест не прошёл.
- Smoke `AcceptedRescheduleTargetsTheMeetingWithoutAHint`: схема extract
  принята, 79 токенов, но событий нет. До match модель не дошла.
  `SummaryPreservesCorrectionAndCitesOriginalSources`: схемы leaf и
  overview приняты, 99 и 86 токенов соответственно, но сводка сохранила
  исправленное исходное значение. Оба теста не прошли.
- Отдельный smoke match с заранее заданным синтетическим результатом extract
  прошёл: схема принята, 104 токена. Это проверка схемы match, а не
  сквозной сценарий извлечения или оценка качества сопоставления.
- В `LivePointsKeepAConcreteDecisionAmidChatter` сырой синтетический ответ
  содержит reasoning, который распознаёт договорённость об использовании
  инструмента записи, но затем заявляет об отсутствии существенных новых
  пунктов и возвращает пустой список. Тест не прошёл. Это подтверждает, что
  в этом примере пустой ответ пришёл от модели, а не отброшен валидатором.
- Модель: `qwen35-sessio-v2.litertlm`, SHA-256 начинается с
  `f2cd2d6c822cb57f`; локальная библиотека `libsessio_litert.so`,
  SHA-256 начинается с `fcd296c22b0c5402`, её точная upstream-версия не
  подтверждена. Backend CPU без fallback; контекст 32768 токенов, резерв
  ответа 4096, greedy decoding (случайный seed не используется).
- По просьбе пользователя составлен и до запуска зафиксирован *новый*
  синтетический набор: 40 кейсов ключевых мыслей и 30 коротких диалогов с
  исправлениями (`test/data/prompter_eval_180.json`, SHA-256
  `ffba5f4ed71ee6e90fb25770c4b136b64a8c5e10e5a28736c63a40a16af5aac2`).
  Это не исторический eval и не репрезентативная выборка встреч; диалоги
  специально сосредоточены на исправлении сроков. Данные синтетические.
- Прогон CPU через пайплайн завершён для 70/70 кейсов. Из 76 вызовов модели
  72 вернули разбираемый JSON-объект (94,7%); шесть кейсов завершились
  ошибкой, включая четыре отмены после лимита 45 с на вызов. Во время
  настройки watchdog первые девять кейсов были выполнены той же моделью и
  схемами без лимита; повторный запуск продолжил файл по идентификаторам.
  Оценка не включает синтаксические ответы, отвергнутые до возврата из
  движка. При сборке использована локальная библиотека, указанная выше;
  версию развёрнутого приложения этим прогоном подтвердить нельзя.
- Проверены сами ответы: на 32 положительных кейсах ключевых мыслей
  31 ответил пустым списком, один отменён по таймауту. Восстановлено 0/32
  ожидаемых фактов; на восьми отрицательных кейсах шесть корректно пустых и
  две отмены (6/8, включая ошибки в знаменателе; среди завершившихся 6/6).
  На 30 диалогах все 27 полученных overview пусты, три завершились ошибкой.
  В одном диалоге задача содержала тему и правильный срок, в одном — оба
  времени с явным исправлением, но без темы; остальные содержательных итогов
  не вернули. Из 12 выданных элементов задачи десять были только знаком
  пунктуации, ID или одиночной буквой. Это качество вывода, а не признак
  успешной работы модели.
- У всех 12 выданных непустых элементов ID принадлежат входу (12/12,
  синтаксическая проверка); у двух содержательных элементов источник
  подтверждает текст (2/2). Отклонённые валидатором сырые элементы в этот
  знаменатель не входят. Явных противоречий среди двух содержательных
  элементов не обнаружено (0/2); этот показатель не характеризует 28
  диалогов без содержательного результата. Упоминание старого значения в
  явной конструкции «не X, а Y» не считалось противоречием.
- Длина leaf note до проверки (UTF-16): 35 ответов, min 0, max 2,
  среднее 0,3; длина итогового overview: 27 ответов, все 0. Числа
  относятся только к этому новому синтетическому набору. Полные синтетические
  ответы и машинный отчёт сохранены в артефактах текущей работы, а не в git;
  распределение ручных оценок по кейсам — в [manual-review.md](manual-review.md).
- Конфигурация проекта и `update_translations` выполнены; Qt lupdate вывел
  предупреждения и ошибки разбора JavaScript в vendored/web исходниках, но
  цель завершилась успешно, незавершённых записей в двух TS-файлах нет.
  Полная проверка GPU и слияние не выполнялись. Старые notebook-варианты
  генератора не менялись и не содержат новой защиты; пересборку и обучение
  не начинать до обновления генератора по отдельной задаче #181.
