# Recurring Calls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** One persistent series invitation resolves to the current occurrence's
room using synchronized recurrence rules, overrides and cancellations.

**Architecture:** Sessio owns the schedule, a durable outbox publishes complete
snapshots to the token backend, and both sides use a shared recurrence module.
The backend resolves one occurrence on demand and atomically obtains its room.

**Tech Stack:** C++20, libical, Qt Widgets/network client, DuckDB, oat++, SQLite,
libsodium and LiveKit. Build on PR #94 head e3cb0e5 in this isolated worktree.

## Global Constraints

- Binding specification: `conflunce/docs/recurring-call-service-spec.md`.
- Delivery sequence: `conflunce/docs/recurring-call-delivery-plan.md`.
- Do not change production, credentials, shared branches or unrelated worktrees.
- Existing single-meeting and ExternalUrl flows remain compatible.
- One schedule writer; full snapshots, CAS revision and atomic replacement.
- No tokens for canceled/no-show/rescheduled occurrences or ambiguous windows.
- No client PII or secrets in logs; check ownership for every practitioner API.
- Follow repository AGENTS.md, use rtk and apply_patch; test-first, focused commits.
- Implementers do not spawn agents. Controller dispatches independent reviews.
- Shared connection access remains serialized; do not open nested transactions.
- Every runtime PR bumps both application versions and CHANGELOG once.
- Scope excludes split series: block “this and following” on published LiveKit
  series with visible explanation. Never silently replace its persistent link.

## Task 1: Shared recurrence and schedule resolution

create `token-backend/test/schedule_tests.cpp`; modify backend/test CMake,
backend vcpkg manifest and Dockerfile, root/event_view CMake only as needed.

**Interface:** library target `pcm_schedule`, namespace `pcm::schedule`, independent
of Qt Widgets/DB/network. Define public `Snapshot`, `Override`, `Occurrence`,
`Resolution` DTOs and `validate(snapshot)`, `occurrencesBetween(snapshot, fromMs,
toMs)`, `resolve(snapshot, nowMs, prejoinSeconds, graceSeconds)`. Use strings for
timezone/local DTSTART/RRULE, int64 UTC milliseconds for identity and intervals.
`Resolution` explicitly distinguishes available/unavailable/ambiguous/invalid/
budget exceeded. Publish exact field names/signatures in the task report for
later tasks. Snapshot includes revision/baseRevision plus complete override and
exception vectors. A successful occurrence exposes originalStartMs/startMs/endMs.

## Verification commands

Backend configure: `rtk cmake -S token-backend -B build-token -G Ninja
-DCMAKE_PREFIX_PATH=<existing dependency prefix> -DPCM_TB_BUILD_TESTS=ON`.
Then `rtk cmake --build build-token --parallel 4` and
`rtk proxy ctest --test-dir build-token --output-on-failure`.
App uses existing vcpkg prefix/system Qt6; configure a new `build-release` in
this worktree (never modify another worktree build). Relevant commands and
RED/GREEN outputs are mandatory in task reports. Before commit: diff --check.

Dependencies and doc status are checked live; no passing build is a call smoke.
