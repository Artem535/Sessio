# Внешние серверы Jitsi

Статус: согласовано пользователем 2026-10-30; реализация и проверка в работе. Требование: подключаться по готовой ссылке и создавать встречи на выбранном внешнем сервере Jitsi.

## Пользовательский сценарий

В «Звонках» остаётся вход по приглашению Sessio и появляется отдельный вариант «По ссылке Jitsi»: ссылка и имя, затем «Подключиться». Код приглашения и шестизначный код доступа относятся только к Sessio. Прямое подключение открывает существующий встроенный звонок с транскрипцией, заметками и суфлёром.

В настройках звонков появляется «Внешний сервер Jitsi», например `https://meet.example.org` или `https://example.org/meet/`. Это сохранённый адрес для создания встреч; ввод готовой ссылки не меняет настройку. При выборе провайдера Jitsi в календаре показывается «Сервер: Sessio / Внешний». По умолчанию сохраняется Sessio. Для внешнего режима показываются сохранённый адрес и пояснение: «Ссылка будет создана на этом сервере. Правила доступа задаёт его администратор». Отсутствующий адрес блокирует создание с переходом к настройке.

При сохранении внешней встречи приложение создаёт непредсказуемое имя комнаты и прямую ссылку локально. Бронирование на сервере не производится: доступность создания комнаты проверяется при подключении. «Скопировать приглашение» копирует прямую ссылку без кода Sessio. Перенос времени сохраняет ссылку; смена выбранного сервера в настройках не меняет существующие встречи. Повторяющиеся встречи остаются только LiveKit.

## Модель и маршрутизация

Добавить `ProviderKind::ExternalJitsi` со строкой `ExternalJitsi`; `Jitsi` сохраняет значение управляемой Sessio встречи. Внешняя встреча хранит URL в существующем `meeting_url`, не имеет backend `meeting_ref` и `invitation_state`. Столбцы уже строковые/необязательные: новую миграцию не добавлять, если проверка DDL не выявит ограничение допустимых значений. Нужен тест сохранения/чтения новых данных. Не распознавать тип встречи по имени домена.

Добавить отдельное действие входа `JoinAction::Kind::JitsiUrl` для календаря и «Моего дня». В список сегодняшних звонков включать внешние Jitsi встречи, сохраняя связь с event ID и текущую политику статусов. Прямой вход из формы не получает event ID. Повторно использовать общий запуск VideoSession/WebCallProvider без фиктивного запроса токена.

Существующий backend-путь и ссылки Sessio остаются самостоятельными. Внешний путь не отправляет адрес сервера, bearer, код доступа или запрос создания в token-backend. JWT Sessio никогда не передаётся внешнему хосту.

## Адреса и совместимость

Один общий парсер принимает HTTPS; HTTP разрешён только для localhost и loopback IP в разработке. Требуются непустой хост и корректный порт; user-info запрещён. Для адреса сервера query/fragment запрещены; путь нормализуется как deployment prefix. Для ссылки встречи отделять последний непустой сегмент комнаты через QUrl, корректно обрабатывать percent encoding и не включать query/fragment в имя комнаты. В первой версии query/fragment ссылки отклоняются с понятной ошибкой: параметры JWT/пароля не должны молча теряться или попадать в логи.

Адаптер загружает `config.js` и `libs/lib-jitsi-meet.min.js` относительно deployment prefix. Использует `config.hosts` и настроенный `config.websocket`, либо `config.bosh`; относительные endpoint разрешаются относительно deployment base. Только при отсутствии обоих используется websocket относительно deployment prefix. Не подменять XMPP домен HTTP-хостом, если сервер указал hosts. Не обещать совместимость со всеми публичными/частными инсталляциями: минимальный контракт — доступный lib-jitsi-meet и гостевой вход, разрешённый сервером.

Серверные скрипты выполняются внутри встроенной страницы и получают доступ к её JS-контексту. Это существующая архитектура, которую расширяет выбор внешнего сервера: адрес должен вводиться пользователем явно; вход по ссылке не должен происходить автоматически от одного открытия URL. Секреты backend не должны присутствовать в этой странице внешнего звонка. Не выводить полные ссылки/параметры и конфигурацию в production-логи.

## Аутентификация и ошибки

Первый объём не включает provisioning JWT, SSO/логин администратора и поддержку всех secure-domain deployment. Нет обещания использовать авторизацию из системного браузера: WebEngine профиль временный. При требовании серверного входа показывать конкретную причину и действие «Открыть в браузере», сохраняя возможность исправить адрес. Открытие в браузере не даёт транскрипцию Sessio.

Пароль комнаты предлагается поддержать отдельным небольшим расширением, если загруженная библиотека предоставляет PASSWORD_REQUIRED и повторный `conference.join(password)`: диалог ввода, повтор при неверном пароле, отмена, без сохранения и журналирования. До проверки этого контракта пароль и lobby считаются неподдержанными состояниями с явным сообщением; бесконечный экран подключения недопустим. Расширение не должно превращаться в реализацию серверного логина.

## Приёмка

Готовая внешняя ссылка подключается без запросов к token-backend; календарная внешняя встреча сохраняется, копирует прямую ссылку и открывается внутри Sessio. Два участника получают отдельные дорожки транскрипции; заметки и суфлёр используют существующий поток. Сервер с deployment prefix и сервер с явно заданным websocket/bosh проверяются отдельно. Некорректный адрес и требование неподдержанной авторизации дают понятную ошибку. Управляемые Jitsi, Sessio-приглашения и повторяющийся LiveKit не регрессируют.

Интерактивную проверку проводить из изолированного профиля. Обычный build, fake adapter и HTTP 200 не подтверждают реальную совместимость внешнего сервера.
