# Проверка транскрипции на Windows

Тестовая сборка ветки `feat/118-call-transcription`, задача #118. Это инструкция
для настоящего звонка, а не отчёт об уже пройденной проверке на Windows.

Готовая сборка: [Windows installer](https://github.com/Artem535/Sessio/actions/runs/37605268191/artifacts/11475675714),
код `9d4a2bd`, версия 0.2.16. Все три платформы прошли этот запуск CI;
публикация релиза пропущена. Архив артефакта Windows занимает около 231 МиБ.

## Установка и подготовка

1. Скачать артефакт `Sessio-windows-installer` из успешного запуска CI, распаковать
   архив и установить `Sessio-windows-setup.exe`. Модель и необходимые DLL входят
   в установщик: Python, GigaAM и ONNX Runtime отдельно устанавливать не нужно.
2. Для проверки использовать тестовые данные. Открыть Sessio в режиме специалиста.
3. В настройках открыть «Транскрипция», включить «Включить транскрипцию звонков».
   Статус модели должен показывать, что GigaAM установлен.
4. Создать тестовое событие на текущее время, открыть звонок и подключить второго
   участника по приглашению. Участник должен заранее согласиться на транскрипцию.
   На двух устройствах использовать наушники, чтобы не записывать эхо динамиков.

## Основной сценарий

1. Нажать кнопку транскрипции в звонке. Без отметки согласия начало недоступно.
   Отмена диалога не должна запускать распознавание или создавать транскрипцию.
2. Снова открыть диалог, отметить полученное согласие и начать транскрипцию.
   Интерфейс должен оставаться отзывчивым во время загрузки модели.
3. По очереди произнести на русском по несколько коротких фраз, с паузами между
   ними. В панели «Транскрипция» должны появиться реплики обоих участников
   с различимыми говорящими и временем.
4. Нажать «Стоп». Фразы сохраняются как черновик, новые реплики не добавляются.
5. Завершить звонок. В карточке события нажать «Транскрипция» — открывается
   отдельная страница внутри Sessio.
6. Отредактировать одну реплику, сохранить её и отметить транскрипцию проверенной.
   Перезапустить приложение и убедиться, что текст и статус сохранились.
7. Удалить транскрипцию с подтверждением. Повторное открытие события не должно
   показывать удалённый текст.

## Дополнительные проверки

- Отзыв согласия во время распознавания останавливает поступление новых фраз.
- Выход из звонка во время транскрипции отключает захват аудио.
- После остановки можно начать новую транскрипцию с новым подтверждением согласия;
  на странице события доступны обе сохранённые транскрипции.
- При прокрутке вверх новые фразы не сбрасывают позицию чтения.
- Пока редактируется реплика, действия, способные потерять несохранённый текст,
  недоступны; «Отмена» возвращает прежний текст.
- В настройках удаление всех транскрипций требует подтверждения и недоступно
  во время активного распознавания.

При ошибке записать версию/commit сборки, шаг, ожидаемое и фактическое поведение.
Для скриншотов и отчёта использовать только тестовые имена и фразы.

## Уже проверено локально

- Два теста реального GigaAM: распознавание русского образца и фразы со временем.
  Также прошли с моделями и sherpa/ONNX Runtime из скачанного CI-RPM; тестовый
  WAV добавлен только как внешний fixture в распакованное временное дерево.
- Полный сценарий с настоящим движком и двумя синтетическими аудиопотоками:
  отказ в согласии, начало, оба говорящих, остановка, сохранение черновика,
  редактирование, отметка проверки и удаление. Повторно прошёл после исправлений
  сборки зависимостей.
- Сборка приложения и проверка временного Linux install tree: модели и приватные
  библиотеки на месте, путь загрузки библиотек настроен.
- CI-RPM распакован без установки: зависимости загрузчика находятся, контрольная
  сумма encoder совпадает с закреплённой, приложение запустилось с изолированным
  профилем и оставалось работающим 25 секунд до явного завершения теста.

Реальный LiveKit-звонок и работа установленного приложения на Windows ещё
не подтверждены этими автоматическими проверками.
