= Суфлёр звонка и автоматическая транскрипция
:toc:

== Статус

Экспериментальная интеграция для CPU. Выбрана Gemma 4 E4B в LiteRT-LM.
Реальный совместный запуск видео, ASR и LLM пока не проверен.
Финальная CPU-проба прошла 10 проверок в восьми синтетических сценариях:
договорённость, перенос, адресная отмена, отсутствие срока, известные сроки,
нейтральные реплики, неподтверждённое предложение и инструкции внутри реплики.
Четыре базовых окна отдельно обрабатывались за 3,5–10,9 секунды.
Под высокой нагрузкой предыдущая версия занимала 33–83 секунды.
Разные промпты и условия нагрузки не позволяют приписать всю разницу одной оптимизации.
Это небольшая авторская проба, а не оценка общей точности или готовности к видеозвонку.

== Настройка

Откройте настройки транскрипции и группу «Локальный суфлёр (экспериментальный)»
и укажите файл Gemma 4 E4B `gemma-4-E4B-it.litertlm`
(https://huggingface.co/litert-community/gemma-4-E4B-it-litert-lm[litert-community/gemma-4-E4B-it-litert-lm]).
Если поле пустое, используется модель из каталога `prompter-models` рядом с приложением.
Модель автоматически не скачивается. Используется CPU, четыре потока;
запуск на Radeon 780M не предусмотрен после сбоя GPU в исследовании.

Модель работает внутри Sessio в отдельном потоке через C++ API LiteRT-LM.
Python и другие внешние программы не нужны. Во время работы суфлёра модель занимает около 4 ГБ памяти;
пауза суфлёра или конец звонка освобождают её.

=== Сборка runtime

LiteRT-LM собирается из исходников один раз, отдельно от Sessio, скриптом `scripts/build-litert-lm.sh`.
Скрипт получает LiteRT-LM v0.18.0, собирает его CMake super-build и создаёт `libsessio_litert`:
наш код на C++ API LiteRT-LM, где наружу видны только функции Sessio.
Abseil, Protobuf, TFLite и остальные зависимости LiteRT-LM скрыты внутри библиотеки
и не конфликтуют с копиями в Sessio.
Upstream проверяет такую сборку только на Ubuntu с GCC 13+; нужны Java 17, Rust, Python 3.12+ с заголовками
(только для скриптов сборки), около 8 ГБ памяти на поток и несколько часов.

[source,bash]
----
scripts/build-litert-lm.sh ~/.cache/sessio-litert-lm
cmake -S . -B build -DSESSIO_LITERT_DIR=$HOME/.cache/sessio-litert-lm/install
----

Без `SESSIO_LITERT_DIR` Sessio собирается с заглушкой: суфлёр сообщает, что runtime недоступен.
Windows и macOS пока не проверены.

Опции автоматического запуска транскрипции и суфлёра первоначально выключены.
Включение автозапуска суфлёра включает автозапуск транскрипции.
Отключение транскрипции отключает обе опции. Согласие участников остаётся обязательным.
После остановки, отзыва согласия или ошибки в текущем звонке автоматической повторной попытки нет.

== Работа во время звонка

В существующей боковой панели есть «Заметки», «Транскрипция» и «Суфлёр».
Суфлёр читает завершённые реплики и предлагает договорённости.
Новые карточки не переключают страницу. Подсказку над переключателем можно скрыть.

Перед принятием сверяйте действие и цитаты. Кнопка источника открывает реплику с временем.
Можно принять, исправить или отклонить карточку. Перенос и отмена требуют вашего подтверждения;
модель самостоятельно не меняет принятые договорённости.
Если цель отмены не определена, выберите договорённость вручную и подтвердите действие.

«В заметки» сохраняет отдельную запись для клиента, связанного с транскрипцией.
При нескольких клиентах выберите получателя. Без клиента договорённость остаётся черновиком;
привяжите клиента на странице транскрипции и затем сохраните запись.
Повторное сохранение одной карточки не создаёт новую заметку.

После звонка откройте транскрипцию и «Проверить договорённости».
Карточки и решения сохраняются локально и включаются в резервную копию.
Удаление транскрипции удаляет данные суфлёра; явно сохранённые клиентские заметки остаются.

== Архитектура и ограничения

Приложение владеет журналом договорённостей. `CallPrompterController` формирует ограниченные окна,
проверяет идентификаторы источников и целей, сохраняет решения с контролем ревизии.
`PrompterWorker` загружает модель один раз на своём потоке и обрабатывает по одному запросу;
остановка отменяет текущую генерацию, отбрасывает её результат и выгружает модель.
Логика извлечения, сопоставления и проверки срока находится в `src/call_prompter/`,
модель получает вход байт-в-байт таким же, как в проверенном Python-прототипе.
При паузе или ошибке необработанные реплики сохраняются для повторной попытки.
Поколение сессии и ревизия защищают от позднего ответа и перезаписи ручных правок.

DuckDB schema 3 содержит состояние суфлёра и отображение карточки в заметку.
Подсказки приватны: другим участникам звонка не передаются.
Вывод модели ограничен и проверяется, однако проверка JSON не доказывает смысловую корректность.
Ошибки распознавания, неопределённые говорящие и неоднозначные отмены требуют ручной проверки.
Суфлёр не даёт медицинских рекомендаций.

В первой версии подсказка проверяет только отсутствие срока у уже извлечённого действия.
Gemma возвращает ограниченный результат проверки, приложение формулирует фиксированный вопрос.
Свободные вопросы о предмете и исполнителе пока не прошли отдельную проверку качества.
Если исходная реплика изменена или удалена, старую карточку нельзя принять или сохранить в заметки.
Отмена с удалением записанного текста очищает также карточки и цитаты в панели.
