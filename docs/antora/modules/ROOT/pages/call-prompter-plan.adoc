= Call Prompter Implementation Plan

____
*For agentic workers:* REQUIRED SUB-SKILL: Use
superpowers:executing-plans to implement this plan task-by-task. Steps
use checkbox (`- ++[++ ++]++`) syntax for tracking.
____

*Goal:* Встроить локальные проверяемые карточки суфлёра в панель заметок
и транскрипции и добавить настройки автозапуска.

*Architecture:* Qt-контроллер хранит очередь и решения пользователя,
отдельный постоянный процесс выполняет CPU-инференс Gemma. Новые
завершённые реплики поступают из контроллера транскрипции. Принятие
карточки использует клиентскую ленту заметок.

*Tech Stack:* C{plus}{plus}20, Qt Widgets/QProcess, существующая DuckDB,
Python worker и установленный LiteRT-LM CPU.

*Spec:* `docs/superpowers/specs/2026-10-13-call-prompter-design.md`.

== Global Constraints

* База `worktree-videoprovider-domain-layer`; ++#++151, отдельная
`codex/151-call-prompter`.
* Только локальный CPU; никаких Radeon-прогонов или автоматического
скачивания модели.
* По умолчанию оба автозапуска false; согласие обязательно; никакого
автоповтора после stop/revoke/error.
* Все изменения договорённостей проверяются пользователем; содержимое
разговора не выводить в логи.
* Сохранить пользовательские заметки и непрерывность звонка при любой
ошибке worker.
* Версия, CHANGELOG, EN/RU, migration/restore tests обязательны перед
PR.

== Review Focus

* Отказ в согласии, модальное окно и завершение звонка: автозапуск не
создаёт сессию после detach.
* Повторный connect того же звонка: ручная остановка сохраняется.
* Поздний ответ после ручной правки: не перезаписывает решение, реплики
остаются для повторного анализа.
* Standalone без клиента: карточка сохраняется до привязки, в чужую
ленту ничего не записывается.
* Delete/revoke/restore: карточки следуют жизненному циклу транскрипции,
сохранённая заметка не дублируется.
