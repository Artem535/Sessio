= Gemma E4B prompt A/B/C, 2026-10-12

== Result

Few-shot examples improve direct agreement extraction on the tested
short set: 11/11 distinct cases pass action/date and exact
source-evidence review, compared with 8/11 for baseline and rules alone.
Both repeats produce identical outputs. This does not solve
rolling-state safety: all three variants delete the meeting when notes
are cancelled. No automatic ledger mutation is accepted.

== Method

Same cached Gemma-4-E4B-it LiteRT export, LiteRT-LM 0.18.0, CPU four
threads, MTP ON, thinking OFF, top++_++k=1, temperature=0, seed146,
context4096. Fresh sessions, no prompt cache or grammar, same short
excluded warmup. No sampling/thinking changes. Model identity is in
xref:research/live-llm-e4b-results.adoc[E4B baseline]. Same template/reference used
previously; initial extraction/patch rendering matches official E4B
template as recorded in xref:research/live-llm-gemma-prompt-guides.adoc[guide
review].

Three variants run sequentially: baseline, reviewed rules, reviewed
rules plus few-shot examples. Exact materialized prompts are in
`spikes/live-llm-bench/prompts`. `prepare++_++prompt++_++ab.py` extracts
candidates from the guide; baseline imported from existing code. Each
variant: 11 short cases x2, control/full history x2, 10 rolling windows
x2. Total138 measured requests. Short output cap160; long/patch256.
Input long tokens: baseline2986, rules3223, examples3353; all fit
without cropping. Seven fixed original rolling windows plus three
mutation windows unchanged. State is generated by the model, never
initialized from an oracle.

Short cases include six original development scenarios and five new
formulations (questions preparation, tentative report delivery,
daily-call refusal, weather, table delivery correction). Few-shot
demonstrations use other actions/dates. These five are authored probes,
not a representative independent test corpus. Repeats establish
reproducibility, not independent quality observations.

CPU-only MemoryMax=5G / MemorySwapMax=0 scopes. Host initially6.9GiB
available, swap essentially full due to other applications. New baseline
is rerun under current conditions; historical timing is not used to rank
variants.

Short medians include six negative cases and wrong answers. They are not
positive agreement latency or time to a safe ledger change. Peak sampled

paired repeats.

Baseline short output requires exact Markdown-fence removal to parse
(22/22). Rules parse20/22: heldout++_++accept is malformed in both
repeats. Other failures: meeting IDs are `++[++u1++]++`/`++[++u2++]++`;
heldout correction puts utterance text in evidence. Baseline misses
acceptance evidence for task and table correction and returns numeric
IDs for heldout++_++accept. Rules{plus}examples parse22/22 as raw JSON,
retain complete actions/dates and exact expected source IDs. No false
agreement in proposal, refusal or weather cases. Parsed schema/evidence
alone was not used as proof of semantic state safety.

All variants retain both accepted agreements with correct current dates
and evidence on the full long-history fixture, as the previous E4B
baseline did. Examples produce an inaccurate hint that the meeting was
changed, though the agreement records themselves are correct. Hint
utility is therefore not passed by the extraction score above.

== Rolling-state failures

Baseline returns empty operations at steps0–6, creates the Friday20:00
meeting at step7, removes it at notes cancellation step8, and finishes
empty.

Rules and rules{plus}examples create meeting `a1` Friday18:00 at step0
and retain it on neutral windows. Both miss the accepted notes promise
at step3. Step7 correctly updates `a1` to20:00 using d1/d2. Step8
incorrectly returns
`++{++"op":"remove","id":"a1","evidence++_++ids":++[++"e1","e2"++]++}`.
Those IDs exist in the current window, so structural guards accept the
wrong target. Step9 leaves empty state. Both replays reproduce this
failure, including the explicit targeted-cancellation example in the
few-shot prompt.

== Decision and limits

Keep rules{plus}examples as a direct-extraction candidate: on this
fixture it improves evidence correctness at about0.98s added median
short latency. It is not proven on real ASR, full calls, diverse
speakers or an independent annotated corpus. Do not call this a
production-ready prompter or safe agreement-state updater. Next state
experiment should isolate event extraction from target matching and
independently reject ambiguous/mismatched cancellation targets. That
architecture has not been tested here. Google sampling and thinking
variants also remain open.

Reproduction: `bash spikes/live-llm-bench/run++_++prompt++_++ab.sh`. Raw
local artifacts:
`results/prompt-++{++baseline,rules,examples}-++{++short,long,patch}.json`,
metadata/logs, and `prompt-ab-manifest.json`. All inference jobs
completed; no product code, GPU test, push or PR.
